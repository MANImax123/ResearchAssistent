# Decisions

All design decisions not explicitly stated in BUILD_INSTRUCTIONS.md are logged here.

| Date | Step | Decision | Rationale |
|------|------|----------|-----------|
| 2026-10-20 | 0.1 | Use `pgvector/pgvector:pg16` Docker image for Postgres with pgvector | Official pgvector image provides PostgreSQL 16 with the extension pre-installed (`ankane/pgvector` is the deprecated name) |
| 2026-10-20 | 0.1 | Use `lfoppiano/grobid:0.8.1` Docker image | Stable, well-tested GROBID release for PDF/TEI processing |
| 2026-10-20 | 0.1 | MinIO via `bitnamilegacy/minio:2025.7.23` (pinned); bucket auto-created with `MINIO_DEFAULT_BUCKETS` | Upstream stopped publishing `minio/minio` on Docker Hub and quay.io (2025). Bitnami's build is the same MinIO server, so the B9 stack is unchanged. Its built-in bucket creation replaces the separate `mc` init container |
| 2026-10-20 | 0.1 | MinIO web console as a separate `minio-console` service (`bitnamilegacy/minio-object-browser:2.0.2`), host port 9001 → 9090 | Bitnami's server image has no embedded console. Log in with `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` |
| 2026-10-20 | 0.1 | GROBID healthcheck uses bash `/dev/tcp` instead of curl | The `lfoppiano/grobid` image has no curl/wget, so the curl healthcheck always reported unhealthy |
| 2026-10-20 | 0.1 | `check_infra.py` maps Docker service hostnames (`postgres`, `redis`, …) to `localhost` and checks pgvector separately | `.env` uses in-network hostnames for the backend containers, while the script runs on the host |
| 2026-10-20 | 0.1 | Neo4j community edition (no APOC initially) | APOC can be added later if needed; community edition is free and sufficient for v1 |
| 2026-10-20 | 0.2 | `/api/v1/health` always returns HTTP 200 with `status: ok \| degraded` and a per-dependency status | The backend's own container healthcheck uses it; a slow or down GROBID should not mark the API itself unhealthy. Each probe runs concurrently with a 3s timeout (`HEALTH_CHECK_TIMEOUT_S`) |
| 2026-10-20 | 0.2 | Added `CORS_ORIGINS` (comma-separated) and `LOG_LEVEL` env vars | Needed for the CORS and logging setup; defaults match local dev |
| 2026-10-20 | 0.2 | Backend image installs dependencies (incl. dev extras) straight from `pyproject.toml`; source is bind-mounted with `uvicorn --reload` in compose | Cached dependency layer, live reload in dev, and `pytest`/`ruff`/`mypy` runnable inside the container |
| 2026-10-20 | 0.2 | `db/session.py` (async engine + `get_db`) created now rather than in 0.3 | The health check needs a DB connection; 0.3 adds models/base on top |
| 2026-10-20 | 0.2 | `.gitattributes` forces LF line endings | Files are bind-mounted into Linux containers; CRLF breaks shell scripts and Makefiles |
| 2026-10-20 | 0.3 | UUID primary keys (`uuid4`) on all tables | Matches `ResearchState` string IDs (B12) and keeps IDs non-guessable in URLs |
| 2026-10-20 | 0.3 | Enums stored as VARCHAR + named CHECK constraint (`native_enum=False`), not native PG enum types | Adding a value later only needs a constraint swap instead of `ALTER TYPE` |
| 2026-10-20 | 0.3 | Removed `backend/alembic/__init__.py` | It turned the migrations folder into a package named `alembic`, which shadows the real library when running from `/code` |
| 2026-10-20 | 0.3 | Initial migration hand-edited: duplicate autogenerated CHECKs removed; cyclic FK `sections.current_version_id → section_versions` added via `op.create_foreign_key` after both tables exist; `CREATE EXTENSION vector` added | Autogenerate output for these cases does not apply cleanly |
| 2026-10-20 | 0.3 | Fields added beyond B11: `files.filename`, `paper_chunks.chunk_index`, `created_at`/`updated_at` timestamps on all tables, unique `(project_id, type)` on sections, `(project_id, name)` on stages, `(project_id, citation_key)` on references | Original filename is needed for downloads; chunk order for context windows; timestamps for dashboards/history; uniques enforce one section/stage/key per project |
| 2026-10-20 | 0.3 | `agent_runs.project_id` and `jobs.project_id` are nullable | Dev/debug LLM calls (1.4) and the demo job (1.3) are not tied to a project |
| 2026-10-20 | 0.3 | `section_versions.content` is markdown text (with `[@key]` citations); `paper_profiles.dataset/metrics/limitations/tech_stack` are JSONB lists | Markdown is what citation scanning and LaTeX/DOCX export consume; profile fields are naturally multi-valued |
| 2026-10-20 | 0.3 | `paper_chunks.embedding` dimension is taken from `EMBEDDING_DIM` (1536); HNSW index deferred to Step 4.4 | The index type and its parameters belong with the retrieval work |
| 2026-10-20 | 0.3 | Replaced `passlib[bcrypt]` with `bcrypt` directly (`core/security.py`) | passlib is unmaintained and breaks with bcrypt ≥ 4.1; input is truncated to bcrypt's 72-byte limit explicitly |
| 2026-10-20 | 0.3 | DB tests use a separate `<POSTGRES_DB>_test` database (auto-created, migrated to head) and roll back each test via savepoints; skipped if Postgres is unreachable | Tests never touch dev data and stay isolated from each other |
| 2026-10-20 | 0.3 | Dockerfile sets `PIP_DEFAULT_TIMEOUT=120`, `PIP_RETRIES=10` | PyPI downloads time out intermittently on the dev network |
| 2026-10-20 | 0.4 | `/auth/login` uses the OAuth2 password form (`username` = email, `password`, form-encoded) and returns `{access_token, token_type, expires_in}` | Swagger's "Authorize" button works out of the box; the frontend sends the same form fields |
| 2026-10-20 | 0.4 | Access tokens only (HS256, `sub` = user id, `type` = "access", lifetime `JWT_EXPIRE_MINUTES`); no refresh tokens yet | Enough for v1; the `type` claim leaves room to add refresh tokens later without accepting them as access tokens |
| 2026-10-20 | 0.4 | `/auth/register` returns the user (201), not a token; duplicate email → 409 | Keeps register and login separate as specified; the frontend logs in right after registering |
| 2026-10-20 | 0.4 | Emails are trimmed and lower-cased; validated with a simple regex instead of `email-validator` | Avoids a new dependency; case-insensitive uniqueness |
| 2026-10-20 | 0.4 | Login with an unknown email still runs a bcrypt check against a dummy hash, and both failure cases return the same message | Response time and message don't reveal which emails are registered |
| 2026-10-20 | 0.4 | Kept `python-jose` (already in pyproject) for JWT; mypy told to ignore its missing type stubs | Avoids a dependency change and image rebuild; can switch to PyJWT later if needed |
| 2026-10-20 | 0.5 | Frontend versions: Next 16.4.0, React 19.3.0, Tailwind 4.3.3, TypeScript 5.9.3, Vitest 4.1.11, jsdom 26.1.0 (all pinned exactly) | Latest releases at least two weeks old. TypeScript 5.9 rather than 7 (the native Go compiler) because Next's type-checking uses the TypeScript JS API. jsdom 26 because 27+ needs Node ≥ 20.19 and the host has 20.18 |
| 2026-10-20 | 0.5 | Access token stored in `localStorage`; session restored on load with `GET /auth/me`; any 401 on an authenticated request clears it and returns to login | The backend issues bearer tokens, not cookies. A later hardening step can move to httpOnly cookies |
| 2026-10-20 | 0.5 | Route protection is client-side (protected `(app)` layout), not Next middleware/proxy | The token lives in the browser, so the server can't check it; the API enforces auth on every request anyway |
| 2026-10-20 | 0.5 | Post-login `?next=` redirect accepts only same-site paths | Prevents open redirects (`//evil.com`, absolute URLs) |
| 2026-10-20 | 0.5 | No ESLint; `tsc --noEmit` is the static check | `next lint` was removed in Next 16; type-checking covers most issues. ESLint can be added later |
| 2026-10-20 | 0.5 | Frontend container runs a production `standalone` build; `NEXT_PUBLIC_API_URL` is a build arg | Small, fast image. For hot reload, run `npm run dev` on the host (see README) |
| 2026-10-20 | 1.1 | Project access through `project_members`: any member can view, owner/editor can edit, only the owner can delete. Non-members get 404, too-low role gets 403 | 404 doesn't reveal that a project exists; roles are ready for member invites (10.1) |
| 2026-10-20 | 1.1 | The raw idea is stored in the project's `research_state` snapshot (`idea.raw_idea`, snapshot version bumped on change), not as a `projects` column | It's the input to the Idea stage, which reads from `ResearchState` (B12) |
| 2026-10-20 | 1.1 | `PATCH /projects/{id}` is a partial update: only fields sent are changed; blank `domain`/`target_venue`/`raw_idea` clear the field; `null` for `title` is rejected (422) | Lets the UI edit one field at a time without resending everything |
| 2026-10-20 | 1.1 | Target venue is a free string; the UI offers `ieee`, `springer_lncs`, `acm`, `elsevier` (matching `backend/templates/`) | Venue configuration and custom templates come in Step 9.2 |
| 2026-10-20 | 1.1 | Project list ordered by `updated_at` desc; editing the raw idea also bumps `updated_at` | "Last updated" on the dashboard reflects any change to the project |
| 2026-10-20 | 1.1 | Project overview lives at `/projects/[id]`; later stage pages will be `/projects/[id]/<stage>` | Shorter URL for the most-used page |
| 2026-10-20 | 1.1 | Project create/update re-read the row with `populate_existing` instead of `expire_all()` after commit | `expire_all()` also expires the current user object, which then lazy-loads, and that fails under asyncio |
